# Первая задача для Codex

Документация определяет будущую игру. Первая реализация выполняет только R0 из [ROADMAP.md](ROADMAP.md), создавая рабочую основу для полного матча R1. Она не должна начинаться с десятков пустых разделов менеджмента.

## Перед запуском задачи

В рабочей базовой ветке должны находиться `AGENTS.md` и эти документы. Если PR с документацией ещё не слит, можно создать ветку реализации от его head и явно указать зависимость. Автоматически сливать документационный или следующий PR нельзя.

Выбрать репозиторий `Troyevv/esport_sim`. Проверка доступа этого репозитория в отдельной среде Codex не выполнена созданием документации; актуальные настройки подключения остаются у пользователя.

## Готовый текст задания

```text
Реализуй этап R0 из docs/ROADMAP.md в репозитории Troyevv/esport_sim.

Сначала прочитай AGENTS.md, README.md, docs/MATCH_SIMULATION.md,
docs/ARCHITECTURE.md, docs/DECISIONS.md и относящиеся требования
docs/GAME_DESIGN.md. Проверь текущее состояние репозитория и ветки.
Если реализация уже начата, продолжи её и не создавай параллельное ядро.

Нужен запускаемый локальный веб-стенд симуляции:
1. Зафиксированные совместимые зависимости и проверенные инструкции запуска.
2. Независимое от FastAPI, SQLite и браузера ядро с симуляционным временем,
   фиксированным шагом, управляемым RNG и сериализуемым состоянием.
3. Одна карта с геометрией препятствий, точками появления и зонами A/B,
   десять агентов 5x5, настоящая навигация, ориентация и видимость.
4. ИИ принимает решения только на основе доступных наблюдений. Движение
   считается ядром; PixiJS отображает полученное состояние.
5. Законченный русскоязычный экран стенда: карта, маркеры и направления,
   время, журнал событий, seed, запуск, пауза, скорость и повторный запуск.
   Отладочный полный обзор явно обозначен и не передаёт знания агентам.
6. Сохранение и восстановление именно реализованного состояния сценария,
   включая RNG и знания, с проверкой совпадения продолжения.
7. Headless-запуск того же сценария и проверки препятствий, видимости,
   одинакового результата при смене скорости/режима отображения.
8. Визуальная проверка работающего интерфейса и первый воспроизводимый
   замер времени/памяти с честным описанием полноты модели.

Рабочий стек: React + TypeScript + PixiJS; Python + FastAPI;
SQLite для постоянных данных по мере появления карьеры; WebSocket для
потока состояния. Версии выбери по совместимости и зафиксируй.
Не добавляй микросервисы, обязательный интернет, аккаунты, мультиплеер,
LLM, импорт десятков тысяч игроков или пустые модули всех будущих систем.

Если проверенной геометрии Mirage нет, используй явно подписанную
тестовую карту с источником/авторством. Она не считается реализацией
реальной Mirage или закрытием требования реальных карт.

R0 — стенд движения и восприятия, не полноценный матч. Не изображай
стрельбу, итоговый счёт, турнир или карьеру, которых ещё нет в ядре.
Для реализованного сценария не сдавай временный MVP-интерфейс,
фальшивые кнопки или отдельно анимированные по скрипту маркеры.

Не останавливайся после схемы/каркаса: доведи указанный сценарий
до запуска, сохранения, проверок и видимого результата.
Нерешённые D-01 и реальные пакеты данных не блокируют этот этап.

Веди работу в отдельной ветке. Ничего не мёрджи и не включай auto-merge.
В финале укажи PR, что работает, реальные команды запуска/проверки,
проведённые тесты, результат визуальной проверки и ограничения.
Обнови README фактическими инструкциями и статусом R0.
Следующий этап R1 не отмечай готовым и не заменяй красивой демонстрацией.
```

## Следующая задача

После приёмки R0 выполняется R1: **полный автономный BO1 на одной карте**, включая решения IGL, оружие/гранаты/бомбу, экономику, счёт из событий, три собственных тайм-аута, обратную связь и сохранение. Детализация R1.1–R1.4 есть в roadmap; объём можно разделить на последовательные PR с явно указанной приёмкой.

Первый полноценный матч принимается до масштабирования мира. Параллельно можно исследовать происхождение карты, реальные составы, регламенты и исторические входы VRS — эти исследования не должны подменять разработку ядра.

## Проверка результата владельцем

Для R0 достаточно проверить заявленный сценарий:

1. Запустить приложение по README, увидеть десять агентов на карте.
2. Проверить препятствия и показ доступной агентам информации в отладочном представлении.
3. Изменить скорость, приостановить и продолжить; данные на карте и в журнале должны согласовываться.
4. Сохранить состояние, загрузить и продолжить; проверить повтор того же сценария по seed.
5. Убедиться, что отсутствующие игровые системы не маскируются готовыми панелями.

Это ручная приёмка конкретного результата, а не замена автоматических проверок ядра.

### Что меняет решение капитана

Капитан сравнивает пользу и затраты допустимых действий при каждом пересмотре. В штатном журнале выбранного действия сохраняются оценки альтернатив, давление по направлениям, свежесть сведений о препятствии, запас времени и оценка пути на второй плент. В снимке остаётся последняя оценка, даже когда приказ продолжает действовать. План сохраняет прежние исполнительные механизмы разведки, входов, C4 и физики гранат. Индивидуальная реакция на контакт, помощь и летящую гранату сохраняет приоритет. [Сравнение альтернатив](../native/attack_options.cpp) · [Исполнение](../native/agent_priority.cpp)

За 358 раундов капитаны выбрали продолжение 1183 раза, ускорение 36, замедление 199, разведку 358, дополнительный рубеж 284, перегруппировку 987, смену плента 88, ложный выход 118, раздельный выход 40 и сохранение 163 раза. Это выдача приказов. В 1925 случаях капитан уже получил хотя бы один ответ по предыдущей действующей редакции, включая собственные сообщения. Оценки используют часы, оборудование живых союзников, их позиции, владение ролью, сыгранность, синхронизацию, знание карты и навыки капитана. Сценарий с одинаковыми сообщениями и разными профилями изменяет и выбор, и время следующего пересмотра.

У смены плента есть стоимость пути, уже пройденной части атаки и недавней перестройки. Чтобы повернуть обратно, нужен свежий контакт на текущем направлении или новое сообщение о препятствии. Привязка к тику наблюдения исключает повторное использование старого сообщения при поздней доставке. На Cache, seed 55302, старт 0, в первом раунде команда повернула на B на тике 437 и обратно на A на тике 607. При втором решении свежая оценка сопротивления на B была 1,71, на часах оставалось 588 тиков при оценке пути на A в 310. Кратчайший интервал между двумя сменами направления во всей выборке составил 51 тик. Сценарные проверки отдельно воспроизводят позднее донесение, нехватку времени и подмену невидимых CT.

При перегруппировке игроки получают достижимые точки сбора и собственные направления наблюдения. Пара на другом входе может удерживать свою позицию. При потере C4 действует штатное назначение на подбор. Для нового сбора после завершения прежнего капитан оценивает изменение состава, недоступность маршрута, расхождение группы и потерю C4. Один и тот же снимок проверен повторно после истечения времени ожидания. Разнесённые группы на 2, 3, 4 и 5 живых протестированы через исполнитель движения.

Для ложного выхода капитан назначает двух игроков без C4 на общий альтернативный вход и отпускает основную группу к действительному пленту. В 5541 тике оба участника действовали на ложном входе и одновременно двигался хотя бы один игрок основной группы. В 4386 из этих тиков по координатам двигались оба участника имитации. На Anubis, seed 55301, старт 0, на тике 156 T2 физически бросил дым на направлении B, T1 продолжал давление, а трое остальных выходили на A. Столбец feintWithCTMove сохраняет исходное измерение смещения CT к пленту, противоположному стартовому. После смены цели это измерение не позволяет установить реакцию CT на действующий приказ. Признак «ложный выход» принадлежит плану T. CT воспринимают обычные звуки и эффекты. Сценарий с потерей двух участников прекращает имитацию. [Сценарии ревью](../tests/test_attack_options.py)

## Решения и исполнение

- **Начало раунда.** Существующий колл учитывает закупку, предыдущие результаты на плентах, игровые навыки, места появления и время подхода по карте. Для раздельного выхода носитель остаётся в основной группе. На второй маршрут выбираются два живых игрока с учётом роли и стоимости пути. При едином групповом выходе используется общий вход. План редактора по-прежнему исполняет штатный обработчик шагов.
- **Разведка.** Пары занимают разнесённые позиции из профиля карты. Игрок сообщает о занятом секторе после осмотра. Потеря позиции, контакт, ослепление и недоступный путь могут изменить донесение. Капитан читает собственный отчёт и доставленные записи других игроков. В его оценку входят свежесть, различие между подтверждённым контактом и звуком, несколько противников на направлении и противоречивость сведений.
- **Ложный выход.** При подходящей закупке капитан поручает разведчику давление на противоположной стороне. Ложная получает приоритет в обычной заявке на закупку. Скаут подбирает достижимую точку по геометрии своего подхода и расходует предмет из инвентаря. Основная группа может сохранить последнюю гранату до выхода. CT воспринимают обычные звуки и наблюдаемые эффекты.
- **Смена решения.** Сопротивление или сообщение о перекрытом маршруте может вызвать смену плента. Капитан оставляет время на путь носителя и установку. При потерях и большом расстоянии между оставшимися игроками он может собрать их около носителя. Ожидание ограничено 28 тиками. После разведки игрок пропускает путевые точки, которые ведут обратно к уже пройденной части карты. После гибели капитана преемник сохраняет план и пересматривает его по своему почтовому ящику.
- **Выход.** Рубеж второго входа использует существующие радиосообщения и таймер личного ожидания. Готовность привязана к сектору, вооружению и положению партнёра. Участник может продолжить движение по времени, при потере состава или под давлением. Внутри групп работают действующие пары, второй номер, поддержка и размен. Люркер может остаться смотреть назад по свежему контакту. Подготовка флешки проверяет ожидаемую физическую точку взрыва и положение союзников. В момент броска действуют обычные восстановление оружия, погрешность игрока и физика гранаты.
- **C4.** На пленте носитель может выбрать доступную соседнюю поверхность, закрывающую известную линию обзора. При малом запасе времени он начинает установку на текущем допустимом месте. Союзник в пределах видимости может остаться прикрывать установку. В постпланте игроки объявляют позиции и распределяют внимание по своим входам. При слышимом касании C4 в составе из трёх и более на той же радарной картине проверяют бомбу наблюдатель и ближайший помощник. Помощник может смениться при перемещении игроков. Штатная оценка пути выхода из зоны взрыва учитывает стоимость оружия и оставшееся время.

Общим для T остаётся назначенный командный план. Радиозадержка действует для сведений разведки и подтверждений на входах. Авторство плана не открывает капитану позиции CT, их инвентарь или личные цели. После установки решения принимают сами игроки. Версия политики записывается в матч и переносится в следующую карту начатой серии. ## Воспроизведение

Сборка и 239 проверок выполняются из корня репозитория в окружении с зависимостями из `requirements-native.txt` и `requirements-test.txt`.

```sh
python -m backend.map_install
python -m tools.build_native
python -m pytest -q tests/test_team_attack.py tests/test_individual_decision.py tests/test_peer_radio.py tests/test_small_groups.py tests/test_group_tasks.py tests/test_grenade_effects.py tests/test_native_match_state.py tests/test_native_physics.py tests/test_cs2_spatial.py tests/test_round_simulation.py
```

Следующие команды повторяют две контрольные и четыре финальные партии на выбранной карте и парный замер CPU. Для матрицы использовать каждый идентификатор карты из CSV. База 55300 общая для сравнения, база 55400 даёт независимые составы. К базе прибавляется индекс карты. Поле `start` указывает, какой из двух составов начинает за T.

```sh
python -m tools.audit_team_attack --map de_dust2 --policy 7 --base 55300 --out work/r554
python -m tools.audit_team_attack --map de_dust2 --policy 8 --base 55300 --out work/r554
python -m tools.audit_team_attack --map de_dust2 --policy 8 --base 55400 --out work/r554
python -m tools.audit_team_attack --map de_dust2 --policy 8 --timing --out work/r554
```

В матч-центре доступен обычный подробный BO1. Журнал стороны показывает причины изменения плана, а статусы игроков — выполняемое действие. JSON аудита сохраняет номера раундов, тики, идентификаторы игроков и примеры координат для проверки на повторе.

# R5.5.4. Командная атака T

На девяти физических картах завершены 36 подробных BO1 финальной политики 8. В 678 раундах T сделали 455 установок. Из 196 коллов смены плента в 95 случаях минимум два живых игрока за следующие четыре секунды приблизились к новому пленту более чем на пять единиц радара. Расчёт использует координаты, включая высоту. На обходном маршруте расстояние до цели может сначала увеличиваться. [Результаты каждого BO1 и примеры траекторий](TEAM_ATTACK_R554.csv)

## Решения и исполнение

- **Начало раунда.** Существующий колл учитывает закупку, предыдущие результаты на плентах, игровые навыки, места появления и время подхода по карте. Для раздельного выхода носитель остаётся в основной группе. На второй маршрут выбираются два живых игрока с учётом роли и стоимости пути. При едином групповом выходе используется общий вход. План редактора по-прежнему исполняет штатный обработчик шагов.
- **Разведка.** Пары занимают разнесённые позиции из профиля карты. Игрок сообщает о занятом секторе после осмотра. Потеря позиции, контакт, ослепление и недоступный путь могут изменить донесение. Капитан читает собственный отчёт и доставленные записи других игроков. В его оценку входят свежесть, различие между подтверждённым контактом и звуком, несколько противников на направлении и противоречивость сведений.
- **Ложный выход.** При подходящей закупке капитан поручает разведчику давление на противоположной стороне. Ложная получает приоритет в обычной заявке на закупку. Скаут подбирает достижимую точку по геометрии своего подхода и расходует предмет из инвентаря. Основная группа может сохранить последнюю гранату до выхода. CT воспринимают обычные звуки и наблюдаемые эффекты.
- **Смена решения.** Сопротивление или сообщение о перекрытом маршруте может вызвать смену плента. Капитан оставляет время на путь носителя и установку. При потерях и большом расстоянии между оставшимися игроками он может собрать их около носителя. Ожидание ограничено 28 тиками. После разведки игрок пропускает путевые точки, которые ведут обратно к уже пройденной части карты. После гибели капитана преемник сохраняет план и пересматривает его по своему почтовому ящику.
- **Выход.** Рубеж второго входа использует существующие радиосообщения и таймер личного ожидания. Готовность привязана к сектору, вооружению и положению партнёра. Участник может продолжить движение по времени, при потере состава или под давлением. Внутри групп работают действующие пары, второй номер, поддержка и размен. Люркер может остаться смотреть назад по свежему контакту. Подготовка флешки проверяет ожидаемую физическую точку взрыва и положение союзников. В момент броска действуют обычные восстановление оружия, погрешность игрока и физика гранаты.
- **C4.** На пленте носитель может выбрать доступную соседнюю поверхность, закрывающую известную линию обзора. При малом запасе времени он начинает установку на текущем допустимом месте. Союзник в пределах видимости может остаться прикрывать установку. В постпланте игроки объявляют позиции и распределяют внимание по своим входам. При слышимом касании C4 в составе из трёх и более на той же радарной картине проверяют бомбу наблюдатель и ближайший помощник. Помощник может смениться при перемещении игроков. Штатная оценка пути выхода из зоны взрыва учитывает стоимость оружия и оставшееся время.

Общим для T остаётся назначенный командный план. Радиозадержка действует для сведений разведки и подтверждений на входах. Авторство плана не открывает капитану позиции CT, их инвентарь или личные цели. После установки решения принимают сами игроки. Версия политики записывается в матч и переносится в следующую карту начатой серии. [Капитан](../native/attack_command.cpp) · [Исполнение выхода](../native/spatial_intent.cpp) · [Постплант](../native/postplant.cpp)

## Зеркальные матчи

Основное сравнение использует одни и те же составы, seed и обе стартовые стороны на каждой карте. Вторая выборка политики 8 использует другие составы и seed. ### Три разбора

1. **Два направления.** Ancient, seed 55300, старт 0, раунд 2, тик 1350. После подтверждения на B один игрок за десять тиков переместился от (354.9, 238.5) к (352.9, 223.5), другой от (230.4, 119.0) к (246.3, 118.0). Стартовые позиции находились на разных входах. Полные координаты XYZ сохранены в CSV.
2. **Смена плента.** В том же BO1 в раунде 5 на тике 3712 IGL сменил направление на B по сопротивлению. Через 40 тиков трое атакующих приблизились к B. У T1 позиция сменилась с (78.9, 149.7) на (114.7, 131.8). Разворот подтверждён маршрутом нескольких игроков.
3. **Ложная на Vertigo.** Seed 55408, старт 1, раунд 2, тик 1359. Разведчик бросил ложную на направлении B. В отдельной проверке из снимка после броска удалили только её активный эффект, сохранив начальные позиции, расходы, журналы, очереди и RNG. На тике 1439 один из CT в исходном прогоне был на 28,7 единицы ближе к B и обходил к пленту через другой вход. В контрольном прогоне он прикрывал смену позиции в Side. Во всей выборке движение CT в сторону имитации наблюдалось у 69 из 102 бросков. Само совпадение по времени не устанавливает причину в остальных эпизодах. ## Замечания PR #45

В таблице только действия атакующей стороны на 18 парных стартах для каждой версии. Тяжёлое ослепление начинается с пика 0,78. Совместное попадание требует урона одной цели от двух разных игроков с интервалом до десяти тиков. Огнестрельная строка исключает HE и огонь из обоих попаданий.

| Метрика T | PR #45, политика 7 | R5.5.4, политика 8 |
|---|---:|---:|
| Раунды | 359 | 366 |
| Флешки / воздействия на CT | 705 / 569 | 634 / 551 |
| Тяжёлые самоослепления / тяжёлые ослепления союзника | 53 / 35 | 7 / 4 |
| Флешки по обязательству группы | 7 | 10 |
| Совместный урон всеми средствами / только оружием | 286 / 170 | 343 / 191 |
| Тики совместного движения по одному парному обязательству | 363 | 293 |
| Установки / обезвреживания CT | 257 / 93 | 257 / 92 |

Тяжёлые самоослепления сохраняются, в том числе из-за погрешности и движения во время полёта. Рост совместных попаданий сопровождается сокращением одновременного движения пары по одному обязательству. Подтверждения между входами считаются отдельно. Для CT сравнение пересмотра плана из одинаковых состояний выполнено на всех девяти картах. В расходах, уроне, зрении и правилах победы коэффициенты для сторон прежние.

## Время, повторы и сохранения

Финальные 36 матчей заняли 604 014 тиков и 269,27 процессорной секунды с наблюдателем траекторий, без загрузки карты и разбора итогового журнала. Максимальный измеренный RSS отдельного процесса после блока тиков составил 393,3 МиБ. Среда — Linux x86_64, AMD EPYC 9V74, квота 4 CPU, Python 3.12.14, GCC 14.2, Release. Пакет геометрии BuildID 26879581. База исходного сравнения — main `bfc6e5f`.

Отдельно на каждой карте из четырёх одинаковых контрольных состояний проиграны окна по 180 тиков без наблюдателя. Порядок версий чередовался, окна повторялись дважды. Медианы по 36 окнам составили 264,9 мкс/тик для версии 7 и 286,3 для версии 8. Медианное отношение в паре окон составило 1,050. На каждом повторе совпал SHA-256 снимка соответствующей версии. [Все замеры](TEAM_ATTACK_R554_TIMING.csv)

В каждом зачётном старте сравнивался живой владелец с восстановленным из снимка на тике 90 через следующие 90 тиков. Сценарии SQLite проверяют ручной и активный слоты после открытия нового экземпляра хранилища, с последующим сравнением полного снимка, включая очереди, журнал и экономику. Проверены отсутствие поля политики и версии 1–8. Все 18 контрольных BO1 совпали с опубликованными хешами PR #45. На финальном бинарном файле отдельно повторена зеркальная пара Dust II для версии 7, с теми же хешами. [База PR #45](GRENADE_COORDINATION.csv)

Всего в работе завершены 72 подробных BO1. В сравнительную таблицу вошли 18 контрольных и 36 финальных. Ещё 16 диагностических матчей использовались для уточнения момента ложного выхода и выбора групповой флешки, 2 повтора — для проверки хешей прежней политики. Тиковые контрфактические проверки завершались внутри раунда.

## Воспроизведение

Сборка и 239 проверок выполняются из корня репозитория в окружении с зависимостями из `requirements-native.txt` и `requirements-test.txt`.

```sh
python -m backend.map_install
python -m tools.build_native
python -m pytest -q tests/test_team_attack.py tests/test_individual_decision.py tests/test_peer_radio.py tests/test_small_groups.py tests/test_group_tasks.py tests/test_grenade_effects.py tests/test_native_match_state.py tests/test_native_physics.py tests/test_cs2_spatial.py tests/test_round_simulation.py
```

Следующие команды повторяют две контрольные и четыре финальные партии на выбранной карте и парный замер CPU. Для матрицы использовать каждый идентификатор карты из CSV. База 55300 общая для сравнения, база 55400 даёт независимые составы. К базе прибавляется индекс карты. Поле `start` указывает, какой из двух составов начинает за T.

```sh
python -m tools.audit_team_attack --map de_dust2 --policy 7 --base 55300 --out work/r554
python -m tools.audit_team_attack --map de_dust2 --policy 8 --base 55300 --out work/r554
python -m tools.audit_team_attack --map de_dust2 --policy 8 --base 55400 --out work/r554
python -m tools.audit_team_attack --map de_dust2 --timing --out work/r554
```

В матч-центре доступен обычный подробный BO1. Журнал стороны показывает причины изменения плана, а статусы игроков — выполняемое действие. JSON аудита сохраняет номера раундов, тики, идентификаторы игроков и примеры координат для проверки на повторе.

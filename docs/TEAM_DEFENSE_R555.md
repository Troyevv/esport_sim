# R5.5.5. Командный интеллект CT

База разработки — `main` после PR #46, коммит `2bc7397`. Перед публикацией ветка обновлена до `7601fa8` из PR #47 с изменениями ROADMAP. После технического ревью новые подробные матчи используют политику 11. Предыдущая версия PR сохранена как политика 10. В матче её видно через маршрут конкретного защитника, направление наблюдения, фактический бросок и действия у C4. Открыть такой матч можно через **Стенд симуляции → BO1 → выбор карты → Запустить**.

## Техническое ревью PR #48

Контроль — коммит `b1bcaad` с политикой 10. Для каждой из девяти карт повторены два подробных BO1 с тем же seed и теми же двумя заявками, с обменом стартовыми сторонами. Затем сыграны те же 18 стартов на политике 11. Все 18 контрольных SHA-256 совпали с исходной приёмкой. Разное число раундов, установок и выполненных ложных выходов в двух ветвях обусловлено развитием матчей. Единица сравнения — один старт на карте. Последующие эпизоды внутри его раундов могут различаться.

### Что изменено по результатам разбора

- **Сигналы и второй плент.** Прежний подбор резервистов проверял домашний плент оставшегося игрока по стартовому назначению. Такой игрок мог фактически находиться в пути. При ограниченном переводе капитан теперь оставляет защитника с учётом NAV-дистанции и свежего донесения о наблюдении. Последующая проверка того же входа снимает более старое свидетельство вблизи точки проверки. Свежий контакт на другом входе сохраняет силу. Для подтверждения перемещения должны совпасть исполнитель, плент, координаты цели и поколение приказа по времени. Изменение скрытого плана T не меняет решение на том же состоянии CT.
- **Отход.** Раньше ослабленный игрок мог получить приказ покинуть плент, к которому ещё только подходил из другого сектора. Капитан теперь считает присутствующих у плента защитников и их здоровье. При выборе рубежа он проверяет проходимость, длину пути, прострел по известным контактам, дистанцию и видимость партнёра. Второй участник получает угол на вход, если видит его с выбранного рубежа. Прогресс и подтверждения поддерживают выданное назначение. Гибель игрока в другом месте больше не переставляет выживших заново. Исполнитель получает задачу отхода в штатном индивидуальном выборе. Зрение, огонь и укрытие сохраняют приоритет во время контакта.
- **Ретейк.** Для каждого игрока капитан хранит чистое время ходьбы и оценку подхода с задержками. По участкам маршрута учитываются доступные капитану сообщения о дыме и огне, углы известных живых соперников, давность и достоверность. Расчёт добавляет время на поиск и зачистку, учитывает пересечение движения с перезарядкой и восстановлением после броска. Далёкий партнёр снижает оценку одиночного входа под подтверждённое сопротивление. При начатом обезвреживании используются исполнитель и фактическое время окончания. Длительность комплекта остаётся частью расчёта. Неизвестная точка бомбы оценивается по площадке и сведениям CT.
- **Прикрытие.** Ближайший помощник отвечает за защиту обезвреживающего. Другие получают отдельные подходы и точки зачистки из контактов, входов и позиций карты. Выбор позиции учитывает видимость назначенного угла и путь, а сообщение напарника резервирует его место. При прерывании действия ближайший защитник в радиусе взаимодействия может начать обезвреживание. В сценарии с гибелью капитана это происходит ещё до завершения выбора нового IGL.
- **Сейв.** Исходный исполнитель брал ближайший выход за границу взрыва и сохранял его до конца. Теперь он сравнивает достижимые выходы в разных направлениях и текущую позицию, если уже вышел. При оценке важны оставшееся время, NAV-путь, известные контакты на маршруте, видимость конечной позиции из района C4 и цена снаряжения. Блокировка пути или свежий контакт дают повод пересмотреть выход. При запасе времени и попадании преследователя игрок может использовать штатное укрытие и ответный огонь.
- **Перегруппировка.** Раньше одного увеличения разброса и потери бойца в любой части карты могло хватить для нового сбора. Учитываются локальная потеря, уход игрока на противоположное направление, исполняемая на рубеже парная задача, новая блокировка и прогресс выданного приказа. Повтор сообщения с того же места сам по себе не перезапускает сбор.

## От сведений до исполнения

Капитан сравнивает удержание исходной расстановки и допустимые действия для каждого плента. При пересмотре он сохраняет оценки в `defenseScores`. Смена решения записывает `defenseCall`, исполнителей и точки назначения в событие `defense_call`. У каждого действия есть условия выполнимости. Например, резерв должен успевать по NAV, а полный перевод требует свежего надёжного наблюдения C4. Капитан использует локальную память и доставленное радио, время наблюдения, радар и снаряжение своей пятёрки, публичную ленту гибелей и геометрию. При оценке давления он учитывает сектор, давность, группу в поле зрения и направление движения. Противоречивое или слабое сообщение исключается из оценки командного манёвра. На обратный перевод требуется новое свидетельство на другом направлении. Стоимость смены приказа убывает с его возрастом. Подтверждение движения даёт резерву время закончить короткий переход при затихающем сигнале. [Оценка и выдача приказов](../native/defense_options.cpp) · [Сбор сведений](../native/defense_review.cpp)

| Решение | Что выполняют защитники |
|---|---|
| Удержание | Продолжают карту стартовой расстановки с её парными проверками, позициями, страховкой и передачей сектора. |
| Усиление, частичная и полная перетяжка | Капитан назначает одного резервиста, второго помощника либо оставшихся мобильных игроков. Выбор учитывает стоимость пути, недоступность сектора по радио и уже занятые позиции. При ограниченной ротации остаётся ответственный за другое направление. |
| Поджим | Пара использует штатное подтверждение готовности на рубеже. Для разведчика капитан ищет достижимую передовую позицию в обзоре страховки и наблюдаемого сектора. Если подходящей следующей позиции нет, действует исходная позиция пары. |
| Возврат контроля | Резерв может унаследовать свободный угол или рубеж выбывшего. Вакантность учитывает напарника, уже принявшего сектор. После выигранной дуэли возможность вернуть пространство опирается на последнее известное положение выбывшего соперника. |
| Перегруппировка | Разошедшиеся защитники одного направления получают разные точки у своего опорного игрока. Повторный сбор после его завершения требует новой потери или донесения о заблокированном маршруте. |
| Отдать плент | При подтверждённом местном превосходстве T и нехватке здоровья защитники получают достижимые разнесённые рубежи вне зоны установки. Встреченный противник по-прежнему может прервать отход. |
| Сейв | До установки один раненый защитник может сохранить дорогую закупку, если замечены C4 на пленте и группа T. После установки капитан сравнивает стоимость попытки с возможностью успеть к C4. |

Начальная расстановка, проверка перекрёстных углов, групповой выход, размен и личный выбор между боем, укрытием и поручением используют существующие исполнители. При гибели или межсайтовом переводе якоря напарник получает освободившийся сектор. После гибели IGL новый капитан продолжает действующий приказ и использует собственные донесения. В парных сценариях с одинаковой информацией замена профиля капитана меняет выбор между удержанием и поджимом, а также срок пересмотра. Изменение владения ролями, синхронизации и сыгранности меняет число действительно назначенных резервистов с одного на двух. На скорость адаптации также влияют чтение игры, знание карты и коммуникация. ## Гранаты, ретейк и часы

Штатная закупка и физика PR #45 определяют, что есть у защитника, где приземлится граната и кого затронет эффект. При начальной расстановке капитан назначает держателя запаса. Последняя граната у него остаётся для позднего раунда при необязательном стартовом броске. Подтверждённый контакт, помощь и срочное тушение сохраняют приоритет. Полученное сообщение о близком однотипном дыме или огне может отменить бросок до расхода предмета. Для флешки проверяется прогнозируемая физическая точка приземления и экспозиция союзников. На ретейке капитан назначает исполнителей гранат по входам и времени подхода. [Исполнение бросков](../native/agent_utility.cpp)

После сообщения о пленте капитан оценивает путь каждого живого CT к центру площадки. Когда ему передали точку C4 или он увидел её сам, расчёт использует доступную поверхность для взаимодействия. Скорость игрока, здоровье, гранаты, набор, время подхода и обезвреживания, численность, недавние известные позиции T и стоимость закупки входят в выбор. Погибший противник исключается по публичной ленте. Приоритет назначения получает игрок с более ранним прогнозом завершения. Если набор рядом, второй CT может занять отдельный угол прикрытия. При потере исполнителя происходит переназначение. У начатого обезвреживания учитывается фактический срок завершения. При запасе до 25 тиков группа пропускает сбор, а ближайший способный игрок может начать работу с C4. [Решение о ретейке](../native/retake.cpp) · [Действия на пленте](../native/postplant.cpp)

### Ложные выходы и смена направления

В наблюдателе действительный плент берётся из текущего приказа T, включая уже изменённую цель. Для ложного выхода требуется движение участника имитации. Проверка якоря требует пережившего окно защитника в пределах 55 единиц от действительной площадки в начале. В 97 из 123 таких окон хотя бы один из этих защитников сохранил близость. При 44 повторных переводах T в 13 окнах хотя бы один CT за три секунды приблизился к новой цели T. На вертикальных картах одно только расстояние до центра слабо различает направления.

На Ancient, seed 55300, старт 0, CT1 был в 15 единицах от A на тике 1654 и в 64 на тике 1684. В геометрической метрике якорь вышел за порог. Оба раза он исполнял свой исходный маршрут Main, а командный приказ CT на A действовал с тика 1618, до ложного выхода. На Inferno, seed 55304, старт 0, во время имитации на A защитники продолжали работать на Banana вблизи действительной цели B. На Nuke, seed 55306, старт 1, T повторно сменили плент на B на тике 216. CT продолжили частичное усиление A, получив собственные контакты там. По координатам один из них при этом приблизился и к B.

Сценарные тесты изолируют причину. Пакет с новым наблюдением C4 меняет исполнение после доставки, старое наблюдение не разворачивает команду повторно. Подмена действительного плана T после физического броска дыма ложной пары на Anubis сохраняет тот же приказ и те же действия CT. Отдельно проверены раздельное давление, повторное подтверждение быстрой группы при одиночном контакте на другом направлении и сохранение второго якоря. ## Воспроизводимость, сохранения и скорость исходной версии PR

Среда измерения — Linux x86_64, AMD EPYC 9V74, сборка Release, Python 3.12.14, геометрия 26879581, правила `cs2-bo1.20`, тик 100 мс. В каждом из 50 зачётных стартов независимый владелец, открытый из снимка на тике 90, дошёл до того же побайтового состояния, что и исходный владелец после ещё 90 тиков. Для ретейка отдельно проверено продолжение из снимка с действующим распределением обязанностей. Активные и ручные слоты SQLite прошли закрытие, повторное открытие и точное продолжение для игр без маркировки и политик 1–10. Версия политики хранится в матче и передаётся следующей карте серии.

Все 18 контрольных BO1 по полному SHA-256 совпали с опубликованными результатами R5.5.4. Финальная сборка дополнительно воспроизвела **72 из 72** опубликованных хешей коротких прогонов политик 8 и 9 из эталонных состояний политики 8. ## Повторение исходного сравнения

В окружении проекта с установленными девятью картами собрать ядро и запустить целевые сценарии.

```sh
python -m tools.build_native
python -m pytest -q tests/test_team_defense.py tests/test_attack_options.py tests/test_team_attack.py
```

Для каждого идентификатора карты выполнить первые две команды. Третья воспроизводит дополнительную зеркальную пару на Ancient, Anubis, Cache, Mirage, Nuke, Train и Vertigo. Последние команды измеряют короткие окна и собирают таблицы.

```sh
python -m tools.audit_team_defense --map de_cache --base 55300 --policy 9 --out work/r555
python -m tools.audit_team_defense --map de_cache --base 55300 --policy 10 --out work/r555
python -m tools.audit_team_defense --map de_cache --base 55400 --policy 10 --out work/r555
python -m tools.audit_team_defense --map de_cache --timing --policy 10 --out work/r555-times
python -m tools.audit_team_defense --out work/r555 --csv work/r555.csv
python -m tools.audit_team_defense --out work/r555-times --timing --csv work/r555-times.csv
```

В CSV пустое поле означает отсутствие зарегистрированного счётчика. Для контрольной политики 9 в исходном прогоне измерялись общие командные попадания, движения, ложные выходы и направления T. Детализация по назначению гранат, секторам огня и выжившим при сейве добавлена для политики 10.

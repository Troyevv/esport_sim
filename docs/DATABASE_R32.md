# R3.2 · База сцены

Откройте **База сцены** на стенде или из матч-центра. В списке пакетов выберите срез и редакцию. Имена команд в базе относятся к конкретной дате. Игра поставляется с заявками на BLAST.tv Austin Major, которые организатор опубликовал 9 мая 2025 года.

В офлайн-пакете сохранены выборочные проверенные факты, один объявленный свободный агент (Perfecto, дата объявления 14 апреля) и результаты финалов IEM Melbourne и BLAST Rivals S1. Статус регистрации игрока на турнир и трудовой контракт — разные сведения. Большой пакет достигает ориентира R3.2 по числу команд и записей игроков. Valve публикует никнеймы. Без постоянного внешнего ID смена ника может дать две записи одного человека, а совпадение точного написания — объединить одноимённых игроков. Точное число уникальных людей неизвестно. Архивные участники не считаются свободными агентами. Игрок без сведений о контракте помечен как неизвестный.

В локальном импорте модель распределяет команды по глобальным местам их пятёрок: 1–16, 17–64, остальные. Получилось 14 команд первого тира, 41 второго и 213 третьего. У 9 названий есть пятёрки в разных диапазонах, поэтому тир команды неизвестен. Это группировка для игры. Официальное приглашение или регламент турнира по ней не рассчитываются.

## Игровые профили

В просмотре игрока показываются имя, возраст на дату среза, национальность, связанные команды, партнёры, история датированных наблюдений, измеренная статистика и игровая подготовка. Обзор показывает шесть ролевых OVR по R3.1 и округлённое среднее этих шести значений как общий OVR. «Навыки · 58» собирает все категории вместе, рядом с числом показывает его происхождение. Цветовые диапазоны 0–39, 40–59, 60–79 и 80–100 дополняют цифру. По профилям клуба, штаба и организации можно перейти к пятёркам и коллегам. Неизвестные даты и контрактные условия видны в карточке.

Ссылка на разрешённый портрет ZywOo ведёт на изображение Wikimedia. При недоступности изображения используются инициалы. Офлайн доступны профиль, источники, статистика, редактор и матч. Компоненты просмотра принимают проекции данных. Виджет рейтингов используется также в матч-центре с разрешённым R3.1 отчётом. Набор навыков ограничивается переданными значениями и допускает диапазоны наблюдений. Полный пакет читает только предматчевый редактор.

## Редактирование и обмен

Выберите раздел, найдите запись по имени, ID или связанному клубу. Фильтр и сортировка действуют на весь результат. В карточке есть переходы к связанным записям, источники и доступная история. В карточке игрока откройте **Навыки · 58**, выберите одну из шести групп. **Редактировать** открывает числовые поля от 0 до 100. В составе можно менять команду, дату заявки, каждого из пяти участников и капитана. Неполную пятёрку можно сохранить для дальнейшего редактирования.

**Создать**, **Копировать** и **Удалить** доступны для всех пяти типов сущностей. У новой записи свой ID. Удалению связанной записи препятствует сервер, в сообщении указана ссылка, которую нужно исправить. Успешная правка создаёт новую редакцию. Старые редакции доступны для чтения, экспорта и запуска матча. **Свой пакет** создаёт независимую редакцию 1 с новым ID и сохранёнными источниками. Это позволяет двум авторам развивать разные варианты одного набора. При конфликте редакций редактор предлагает перечитать пакет.

**Экспорт** скачивает JSON с полями `package` и `sha256`. **Импорт** проверяет каноническое содержимое (UTF-8, сортировка ключей, компактный JSON), повторяющиеся ключи, ID, даты, диапазоны, источники, ссылки и версии. Импорт идентичной редакции повторяем. Совпадение ID и редакции при разном содержимом вызывает ошибку. Одна транзакция SQLite записывает целую редакцию; ручной слот и активный матч живут отдельно. SHA-256 выявляет изменение содержимого, авторство источника проверяют отдельно. Лимит одного файла — 24 МиБ.

## Повторить подготовку

Из корня проекта, с Python из штатного окружения:

```console
python -m tools.import_scene --output austin.json
git clone --filter=blob:none --no-checkout https://github.com/ValveSoftware/counter-strike_regional_standings.git valve-standings
python -m tools.import_scene --valve-repo valve-standings --output valve-may.json
```

Импортируйте полученный файл в редакторе. В BAT и EXE тот же импортёр также принимает **ZIP из 297 исходных Markdown-файлов**. Выберите его кнопкой **Импорт**. Если у вас уже есть каталог `invitation/2025/details/2025_05_05`, достаточно упаковать его обычным архиватором. Для клона Git доступна команда:

```console
git -C valve-standings archive --format=zip -o ../valve-may.zip f8c55f250fdef796d708aa32814587932154fa04 invitation/2025/details/2025_05_05
```

Программа проверяет SHA-256 каждой исходной карточки и комплектность до записи пакета. Файлы ZIP обрабатываются в памяти. При чтении текстовых входов нормализуются окончания строк CRLF. Экспорт всегда создаёт единый пользовательский JSON. Сборщик читает объекты Git из коммита `f8c55f250fdef796d708aa32814587932154fa04`, каталога `invitation/2025/details/2025_05_05`. Для частичного клона получение недостающих объектов использует сеть. Повторная сборка из локального полного набора объектов и сама игра работают офлайн. Публикация Valve ссылается на данные HLTV. Условия на массовое распространение выгрузки в составе игры не подтверждены, поэтому в репозитории и ZIP находится адаптер и малый автономный набор. Исходные статьи и логотипы не включены. Профиль ZywOo ссылается на отдельно лицензированный портрет. [Доступ и ограничения](../SOURCES.md)

Строка состава в Valve фиксирует наблюдение на дату рейтинга. Одно название может соответствовать нескольким рейтинговым пятёркам, один спортсмен может встречаться в разных заявках. Разные пятёрки одного бренда получают отдельные ID. Название команды на карточке исторической встречи обозначает линию состава в отчёте Valve. Фактическое название клуба в день встречи могло отличаться. ID матча имеет область действия этого снимка Valve. Две точки зрения одной встречи получают разные записи с одним исходным номером. Предыдущие пятёрки, противник, дата, W/L и ссылка на исходную карточку сохраняются. Призовые, полный календарь, начало и конец трудового договора из этих строк не следуют. Данные для воспроизведения официального VRS неполны.

## Откуда берётся число

У записи есть источник по умолчанию и переопределения для отдельных полей, в том числе для отдельного навыка. Вкладка **Источники** показывает дату наблюдения или оценки и ссылку либо описание метода. Пустое поле означает неизвестное на дату среза. Ручная правка получает метку «Модель» с текущей датой сервера. Отсутствующий навык в пользовательском файле считается ошибкой формата.

* **Подтверждено** — факт из источника, например ник или заявка. Даты регистрации и публикации даны отдельно от даты проверки источников.
* **Расчёт** — приближённая игровая оценка по наблюдениям. Для десяти участников финала BLAST Rivals S1 использован опубликованный ADR за пять карт. Версия 1 оценивает только AIM. Центр ADR для моделируемой роли IGL — 68, поддержки — 70, снайпера и энтри — 76, остальных — 74. Поправка за соперника равна `4 × max(0, (31 − место) / 30)` по близкому срезу 5 мая. Для финала использованы места Falcons 3 и Vitality 1. Итог равен `65 + (0,7 × (ADR − центр) + поправка) × n / (n + 12)` с округлением до целого и ограничением 0–100. На пяти картах вес наблюдения всего 5/17. Роль для формулы — игровое назначение. Центры и коэффициенты заданы как допущения модели. ADR зависит также от раундов, экономики и гранат. По одной серии точность AIM человека измерить нельзя. [Таблица матча BLAST](https://blast.tv/cs/tournaments/blast-premier-rivals-season-1-2025/match/bfaaa42e/falcons-vitality)
* **Расчёт в пакете Valve** касается только исполнения тактик. Для матчей с известной позицией противника ожидаемая доля побед равна 0,40 / 0,50 / 0,60 для трёх групп соперников. Используется лучшее место названия в срезе. Учитывается присутствие конкретного ника в исторической пятёрке. Противоречивые наблюдения пропускаются, одинаковый ID учитывается один раз на игрока. Оценка равна `65 + 12 × сумма(победа − ожидание) / (n + 20)`. Это слабая командная оценка с большой неопределённостью и смещением из-за ретроспективного рейтинга. Независимый вклад отдельного игрока, его роль или точность стрельбы по этой истории определить нельзя.
* **Модель** — нейтральные 65 баллов по неизмеренным навыкам. Потенциал остаётся пустым. Игровым числам мотивации, лояльности и других личных черт соответствует одинаковая метка модели. Значение 65 даёт движку исходное состояние при отсутствии измерения. Ролевые веса и воздействие 53 навыков на BO1 сохранены из R3.1. [Модель мира](WORLD_R31.md)

## Матч и сохранение

Откройте **Подбор BO1**, выберите свои пять игроков через состав, соперника и seed, нажмите **Начать BO1**, затем **Запустить** в матч-центре. В сценарий копируются десять профилей, их команды, относящийся к ним штаб и ID редакции пакета. Матч требует разные команды и десять разных игроков. Для неустановленных ролей используются назначения игровых слотов, при неизвестном капитане назначается первый игрок. Форме и морали присваивается 50, усталости 0, освоению роли и знанию «Депо» по 65; языки и наблюдения отсутствуют. Технический владелец команды с неизвестной организацией нужен для проверки прав тренера. Эти допущения действуют внутри выставочного матча. Счёт складывается из событий обычного BO1. Сохранение содержит собственный снимок и после перезапуска переживает изменения пакета.

Контрольные прогоны на Linux x64, Python 3.12.14, правила `depo-bo1.2`, десять игроков на карту:

| Матч | Seed | Счёт | События | Тики |
|---|---:|---:|---:|---:|
| Vitality — Falcons | 42 | 8–13 | 3 999 | 11 760 |
| M80 — TYLOO | 47 | 16–13 | 5 274 | 15 452 |
| The MongolZ — FURIA | 91 | 13–7 | 3 745 | 10 787 |

Повтор проверки: `python -m pytest -q -s tests/test_database.py`. Для браузера после сборки frontend выполните `npm test -- database.spec.ts` в каталоге frontend. Тест переключает группы навыков, сохраняет правку, проходит по ссылке состава, экспортирует и импортирует файл, открывает реальный BO1. Размеры экранов заданы в конфигурации Playwright.
